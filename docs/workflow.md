# v2 端到端工作流

## Phase 0：输入清点

读取 Word、PDF、Markdown、图片、已有 PPT、数据表和视频。输出来源清单、术语表、版权/隐私限制和缺失信息。医疗或科研内容必须区分“原始证据”“作者解释”“生成性示意”。

## Phase 1：主题与叙事

确定：听众、汇报场景、目标、时长、页数、语言、结论、不能声称的内容。先写 `outline.md`，再写 `deck_spec.json`。每页必须有一个主张、一个证据角色和一个建议版式。

闸门 G1：人工确认大纲、页数和重点。未确认不得生成全套页面。

## Phase 2：素材计划

把素材分成四类：

- 必须保真的原图：论文图、CT 截图、实验照片、Logo、表格截图；
- 可重新绘制的结构图：流程、架构、决策树、时序图；
- 可计算的图表：柱状图、折线图、散点图、混淆矩阵；
- 可生成的视觉：封面背景、概念插画、章节视觉。

每个素材写入 `asset_manifest.json`，包含来源、用途、是否允许编辑、是否允许模型重绘、最低分辨率和版权备注。

## Phase 3：风格与后端

给出 2–3 个风格方向，明确：配色、字体、网格、标题规则、图表规则、图像风格、页面密度和页间节奏。再选择后端：原生 PPTX、整页图片、HTML 截图、视频或混合模式。

闸门 G2：人工确认风格、可编辑性目标和后端。后端确认后，本轮不随意切换。

## Phase 4：单页样张

选择最能暴露风险的一页，不选最简单的封面。对于当前任务，建议选“真实病例 + 三态判定”页或“总流程”页。样张必须包含真实文字长度、真实数据和指定素材。

闸门 G3：人工确认文字清晰度、信息层次、图片与文字关系、风格和投影可读性。

## Phase 5：逐页生成

每页建立 JSON job，记录页面角色、输入素材、禁用内容、提示词、后端、输出路径和验收条件。并行生成只适用于页面之间相互独立的阶段；主控代理负责状态、命名、汇总和最终 QA。

## Phase 6：质量检查与修复

自动检查：文件可打开、页数、媒体、文本框边界、重复标题、缺失素材、低分辨率图片、备注、状态闭环。人工检查：医学图像保真、关键结论、字体替换、视觉节奏、演示现场可读性。

高严重度问题必须修复后才能组装；中严重度问题要记录是否接受。

## Phase 7：演讲稿与组装

生成 `speech.md`，每页包含目的、讲述顺序、证据解释和过渡句。组装 PPTX 时保留页面图片、原图、备注、来源标记和 QA 报告。

## Phase 8：验收与复盘

输出 deck、演讲稿、素材清单、状态记录、QA 报告和下一轮建议。每轮实验必须说明：用了什么后端、哪些页面由人工决定、失败发生在哪一层、下一轮改变什么。
